# 收集与不确定论文调查

规则版本 3，更新于 2026-11-07。

候选初筛覆盖 anomaly、defect、industrial、manufacturing、inspection、outlier 及主要工业三维基准。初筛追求覆盖，最终由模型按研究任务与评测场景判定。摘要未命中工业关键词不会阻止模型评审，没有摘要的候选也能进入调查。

DeepSeek 输出四类决定。

- keep，有公开证据支持工业视觉异常、缺陷检测，以及直接服务这些任务的数据、评测或合成工作。
- reject，有明确的不相关证据，例如仅进行医学、金融或时间序列实验。
- verify，需要调查具体数据集、工业评测或任务场景。
- pending，调查后证据仍不足，或本轮预算耗尽，等待后续运行。

跨工业与医学的研究可以收录。没有列出数据集名称本身不是排除理由。模型通过来源编号给出原文引用，程序将编号映射为实际来源 URL，并检查引用是否确实包含在已提供的资料中。无效引用丢弃；保留下来的有效引用仍须单独满足范围要求，才能收录。引用及程序提取的相邻原文（前后各最多 240 字符）还必须覆盖工业场景、视觉模态与异常/缺陷任务，否则进入调查，调查后仍缺证据则保持 pending。工业时序根因分析、无直接缺陷检测实验的图像预处理不在范围内。这是保守的收录检查，不能替代模型的语义判断，也可能让表述特殊的相关论文继续等待证据。

每篇深入调查使用论文标题（过长时取连续片段以满足搜索接口 128 字符限制），并结合模型提出的疑点，最多执行三次搜索。最多尝试六个不同链接，保留三个正文包含论文标题的来源。支持官方出版站点、arXiv 摘要/HTML、GitHub 仓库 README 和 github.io 项目页。其他作者自建域名暂不读取。匹配标题用于减少同名及错配，不能独立证明仓库作者身份。

搜索摘要不直接作为收录证据。读取器限制来源、检查重定向与响应类型，拒绝 PDF 和下载入口，不下载代码、不执行页面内容。页面提供的指令不能改变模型任务。

每轮预算保存在 config.json。

| 项目 | 上限 |
| --- | ---: |
| 模型判断请求，含复核及格式重试 | 400 |
| 深入调查论文 | 60 |
| 每篇调查搜索 | 3 |
| 每来源补取详情 | 40 |
| 补查代码链接 | 15 |

模型仍为 deepseek-flash，仓库变量 DEEPSEEK_MODEL 可覆盖。搜索 API 与模型判断分别计数。计数按逻辑请求统计，底层网络重试最多三次，不另计入这两个计数，因此它们不等同于实际 HTTP 请求数或账单条数。调查的文本、搜索记录和引用保存在 papers.json 对应论文中，GitHub Actions 摘要显示调查数量。尚未完成的候选优先处理有工业视觉线索的条目，同组优先复核已有证据的条目，再按尝试时间排队，后续每周继续检查。代码链接补查仍使用已有独立核对规则，调查找到的链接不会未经处理直接替换正式会议信息。

版本 2 曾将版本 2 以前的 rejected 重新送审；版本 3 不重复处理这批已排除记录，但会重新复核版本 2 的新增收录。原有历史收录保留。本次改变不代表已建立独立于模型的全面内容验收，已收录的历史条目也不保证都具备新版证据字段。

手动运行可选择 review_only，只复核存量候选，不重新扫描目录、不推进采集时间；报告保留上次完整采集的失败来源，复核成功不等于所有采集来源恢复。每周定时运行仍执行完整采集。

单次接口请求最多重试三次。单条调查搜索失败会记录错误并继续其他搜索及已有作者链接；单篇模型请求失败先保留待处理，连续四篇出错才中断。本轮遇到密钥、权限或余额错误会立即停止模型复核。长网页提取跳过导航，并避免重复截取相邻片段挤掉实验正文。

模型输出不符合结构时，带具体错误提示重试一次。调查后仍要求继续核实的结果统一保存为 pending。调查成果在最终模型判断失败时也保留，下一轮可直接利用已有证据。

明确报告已完成工业检测实验且说明视觉模态的论文，不要求必须给出数据集专名；仅泛泛声称潜在工业用途不足以收录。引用的相邻上下文由程序从实际来源截取并保存，避免半句引用遗漏模态描述。

## 持续追踪新年份（2026-11-08）

生产配置不再固定 collection_year；2026 是开始收集的年份，不是结束年份。已有论文永久保留在清单中，未来按各自会议/期刊年份展示。官方来源规划每次自动覆盖从 2026 到当前年份加一；arXiv 按上次成功时间增量采集，不受 2026 上限限制。显式写了 submitted/under review 的 arXiv 声明不当成正式会议归属。

每个“来源＋年份”在 state.json 的 source_lifecycle 中分别记录状态、目录指纹、最近变动时间及下次检查时间：

- active：默认每 7 天扫描。目录内容变化才再次调用该来源的 DeepSeek 补漏搜索；首次检查、尚未成功搜索或搜索失败也会搜索。即使目录不变，仍按原规则补取详情、复核存量候选。
- awaiting_catalog：尚未找到可识别的正式论文目录，每 14 天探测；可能尚未发布，也可能页面结构变化，不等于确认没有论文。发现目录后自动转为 active。
- dormant：至少三次无变化、且持续 90 天稳定后，每 90 天检查一次，发现变化自动恢复 active。当前及上一年度期刊不进入此状态，以保留期刊连续出版和延迟补录窗口。仍有详情排队或失败时提前至 7 天再检查。
- closed：只有 rolling.overrides 中明确设置 closed、reason、evidence_url 才永久停止该届来源采集及补漏搜索。没有依据时不会因“会议已结束”自动永久关闭。已有待核实论文仍可复核。
- not_scheduled：根据会议届次安排跳过，例如偶数年的 ICCV、奇数年的 ECCV。

此前正常的目录变空、无法解析或请求失败会报错，并保留上次成功指纹，不会自动关闭。目录指纹覆盖论文标识、标题和已有摘要。未变化时停止重复的两条 DeepSeek 来源搜索，也意味着这两条搜索暂不承担从未变化的目录中反复寻找漏项的任务；候选初筛和模型仍可能漏检。

ICML 卷号从 PMLR 官方索引按会议和年份识别，不猜数字；ICLR 支持论文集与正式录用页面两条入口。未发布新年目录时不把投稿名单当录用名单。期刊查询回看前一年出版日期，并以正式印刷年份优先归类，覆盖提前上线、次年编卷的情况。

每年无需手工把 2026 改成 2027，但官网换结构仍可能需要维护解析器。历史对照验收单独指定 year，默认 2026，不影响持续采集。

新年份地址必须通过内容年份校验。NeurIPS/ICLR 卡片式目录的页面标题必须明确对应目标届次；未来年份网址即使返回 HTTP 200，也不能据此认定目录已发布。2026-11-08 实际发现 NeurIPS 2027 地址返回 2026 页面，已恢复被错误改年的 76 条记录，并将此情况加入自动回归检查。
